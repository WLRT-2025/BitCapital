# Repository Map

## Purpose

This document explains the role of the main public repositories associated with the broader WLRT / WaveCounter / BitCapital / KEFEN ecosystem.

Its purpose is to help readers understand where to find the theoretical framework, where to find applied system materials, where token-related documentation is maintained, and where BitCapital’s internal research-pool layer is documented.

## Main Repositories

| Repository | Primary role |
|---|---|
| WLRT | Foundational theoretical and methodological repository for Wave Liquidity Redistribution Theory |
| WaveCounter | Applied conceptual and engineering framework built on WLRT |
| wavecounter-engineering-canon | Canonical engineering / configuration layer for WaveCounter system logic |
| kefen-registry | Public documentation and registry anchor for KEFEN |
| BitCapital | Public documentation for the BitCapital applied implementation and Research Pool layer |
| MALN | Related structural or network-oriented research direction within the broader ecosystem |

## WLRT

The `WLRT` repository is the foundation layer of the ecosystem.

It is the place where the theoretical and methodological basis of Wave Liquidity Redistribution Theory is documented and developed. Readers looking for core concepts, structural reasoning, and the origin framework for later systems should begin there.

## WaveCounter

The `WaveCounter` repository represents the applied conceptual and engineering direction built on top of WLRT.

It should be read as the bridge between pure theory and more concrete system logic, practical playbooks, and future applied technologies.

## wavecounter-engineering-canon

The `wavecounter-engineering-canon` repository serves as a more canonical engineering and configuration layer.

It is the place for more formalized system descriptions, structured specifications, and core implementation logic related to WaveCounter engineering architecture.

## kefen-registry

The `kefen-registry` repository is the public documentation and registry anchor for KEFEN.

It exists to provide a stable public reference point for KEFEN-related materials, including identity, documentation, links, token-related descriptions, and associated ecosystem references.

Readers interested specifically in KEFEN as a token should begin there, then use linked materials to understand its broader architectural role.

## BitCapital

The `BitCapital` repository documents the applied implementation and internal research layer of the ecosystem.

Its primary focus is the BitCapital Research Pool, related policy materials, ecosystem architecture, and the evolving role of KEFEN within a WLRT / WaveCounter-based structural liquidity environment.

Readers interested in how WLRT and WaveCounter ideas are tested in a live internal setting should begin with this repository.

## MALN

The `MALN` repository represents a related structural research direction inside the broader ecosystem.

It may be read as a connected but distinct line of work relevant to liquidity systems, network structure, propagation logic, or high-dimensional system behavior.

## How the Repositories Relate to Each Other

The intended relationship between the repositories can be summarized as follows:

1. `WLRT` provides the foundational theory.
2. `WaveCounter` develops the applied conceptual and engineering direction.
3. `wavecounter-engineering-canon` formalizes core engineering and configuration logic.
4. `kefen-registry` provides the public token-specific reference layer for KEFEN.
5. `BitCapital` documents the applied implementation and internal Research Pool layer.
6. `MALN` extends related structural research in a connected domain.

## Suggested Reading Path

For a reader new to the ecosystem, the following reading path may be useful:

1. Start with `WLRT` for the theoretical basis.
2. Continue with `WaveCounter` for applied conceptual direction.
3. Review `wavecounter-engineering-canon` for more formal engineering structure.
4. Read `BitCapital` for the internal applied implementation and Research Pool context.
5. Use `kefen-registry` to understand KEFEN’s public documentation and token reference layer.
6. Explore `MALN` as a related structural research branch.

## Notes

Repository roles may evolve over time as the architecture becomes more detailed and as new documents, software layers, operator models, or licensing structures are introduced.

This document is intended only as a public orientation map for the current repository structure.
